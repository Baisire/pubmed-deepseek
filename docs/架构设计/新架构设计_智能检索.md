# 新架构设计 - 智能文献检索工具（Streamlit）

> 项目编号：a6 | 设计日期：2026-07-30 | 架构版本：v2.1
> 核心变更：从"关键词直传 esearch"升级为"LLM+MeSH 智能查询优化 + 自适应多轮检索 + 引文排序"

---

## 一、问题诊断

### 当前架构的致命缺陷

```
当前流程：用户关键词 -> esearch（原样传入）-> efetch -> DeepSeek 分析
```

`app.py` 第 360 行，用户输入的 `"diabetes treatment"` 直接作为 `term` 参数传给 esearch，导致：

| 问题 | 原因 | 后果 |
|------|------|------|
| 无 MeSH 映射 | 自然语言未转换为 MeSH 主题词 | 漏掉标引了 MeSH 但标题/摘要中不含该词的文献 |
| 无 Boolean 逻辑 | 单一字符串匹配 | 无法表达"概念A AND 概念B"的多维度检索意图 |
| 无字段限定 | 未使用 `[MeSH Terms]`、`[Title/Abstract]` | 全文匹配噪声大，相关度低 |
| 无同义词扩展 | 单一关键词 | 漏掉同义表达的文献（如 neutropenia / neutropenic / neutropaenia） |
| 无结果排序 | 仅靠 PubMed 默认 relevance | 高被引经典文献可能排在后面 |
| 无相关文献扩展 | 仅返回 esearch 直接匹配 | 漏掉语义相关但关键词不同的文献 |

### .nbib 文件的启示

两个 .nbib 文件中的 `MH` 字段展示了专业检索式应该具备的要素：
- **MeSH 主题词 + 子树限定符**：`Neutropenia/*chemically induced`
- **多维度概念组合**：疾病 + 预测因子 + 化疗 + 风险
- **同义词并列**：`Monocytes` + `monocyte count` + `monocytopenia`

这些文件作为**参考信息**指导架构设计，不直接集成到代码中。

### 与 v2.0 的关键差异

| 维度 | v2.0 | v2.1（本版） |
|------|------|-------------|
| MeSH 验证 | esearch+esummary 两步，串行 | MeSH REST API 一步 + 并行 + SQLite 缓存 |
| 引文排序 | Semantic Scholar 为主（限流严重） | PubMed elink citedin 为主，Semantic Scholar 可选增强 |

| 缓存 | 无 | MeSH 术语 + 引文数据 SQLite 缓存 |

## 四、核心流程详解

### Step 1：智能查询优化（query_optimizer.py）

#### 1.1 流程

```
用户自然语言输入
  例："化疗后中性粒细胞减少的血液学预测因子"
        ↓
  ┌─────────────────────────────────────┐
  │  1.2 LLM 概念拆解（DeepSeek）        │
  │  输入：自然语言                       │
  │  输出：结构化 JSON                    │
  │  - core_topic                        │
  │  - concepts[]                        │
  │    - name                            │
  │    - english_terms[]                 │
  │    - mesh_candidates[]               │
  │    - synonyms[]                      │
  └──────────────┬──────────────────────┘
                 ↓
  ┌─────────────────────────────────────┐
  │  1.3 MeSH 术语验证与扩展（并行+缓存） │
  │  对每个 mesh_candidate：              │
  │  - 先查 SQLite mesh_cache            │
  │  - 未命中则调 MeSH REST API           │
  │  - ThreadPoolExecutor 并行验证        │
  │  - 验证结果写回缓存                   │
  └──────────────┬──────────────────────┘
                 ↓
  ┌─────────────────────────────────────┐
  │  1.4 自适应检索式生成                 │
  │  生成三档检索式：                     │
  │  - 窄：全 MeSH + 全 AND              │
  │  - 中：MeSH + 自由词 + AND（推荐）    │
  │  - 宽：自由词 + 同义词 + OR           │
  │  先用中档 esearch 取 total_count      │
  │  自动选择最合适档位                   │
  └──────────────┬──────────────────────┘
                 ↓
  返回 SearchStrategy
```

#### 1.2 LLM 概念拆解提示词

```

【任务说明】
将用户的自然语言查询拆解为核心概念维度，每个维度提取英文检索词、MeSH候选词和同义词。

【输入格式】
用户自然语言查询字符串

【输出格式】（严格 JSON，不要 Markdown 代码块标记）

  "core_topic": "一句话描述研究方向",
  "concepts": [

      "name": "概念维度名称（中文）",

1. 识别 2-4 个核心概念维度

      "english_terms": ["neutropenia", "febrile neutropenia"],
      "mesh_candidates": ["Neutropenia"],
      "synonyms": ["CIN", "FN", "neutrophil nadir"]
    },
    {
      "name": "血液学预测因子",

      "english_terms": ["chemotherapy", "chemotherapy-induced", "predictor"],
      "mesh_candidates": ["Antineoplastic Agents"],
      "synonyms": ["cytotoxic chemotherapy", "risk factor", "prognostic"]
```

#### 1.3 MeSH 术语验证（mesh_lookup.py）-- 优化版

**优化点**：用 MeSH REST API 一步查找代替 esearch+esummary 两步走；并行验证；SQLite 缓存。

```python
def lookup_mesh_term(term: str) -> dict | None:
    """验证 MeSH 术语是否存在，返回精确信息。

    优先查 SQLite 缓存，未命中则调 MeSH REST API。

    API（一步到位）:
        GET https://id.nlm.nih.gov/mesh/lookup/descriptor?label={term}&max=1
        -> [{"resource": "http://id.nlm.nih.gov/mesh/D009504", "label": "Neutropenia"}]

        再取详情:
        GET https://id.nlm.nih.gov/mesh/D009504.json
        -> {
             "identifier": "D009504",
             "label": {"@value": "Neutropenia"},
             "treeNumber": ["http://id.nlm.nih.gov/mesh/C15.378.553"],
             "allowableQualifier": [...],
             "concept": [...]  // 含入口词/同义词
           }

    返回：
        {
            "term": "Neutropenia",
            "ui": "D009504",
            "tree_numbers": ["C15.378.553"],
            "entry_terms": ["Neutropenias", "Neutropaenia"],
            "subheadings": ["chemically induced", "diagnosis", ...]
        }
    或 None（术语不存在）
    """
```

**并行验证**：
```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def verify_mesh_batch(candidates: list[str]) -> dict[str, dict | None]:
    """并行验证多个 MeSH 候选词。

    ThreadPoolExecutor(max_workers=3)
    每个 candidate 调 lookup_mesh_term()
    返回 {candidate_term: result_or_none}
    """
```

**SQLite 缓存表**（在 db.py 中新增）：
```sql
CREATE TABLE IF NOT EXISTS mesh_cache (
    term TEXT PRIMARY KEY,
    ui TEXT,
    tree_numbers TEXT,      -- JSON array
    entry_terms TEXT,       -- JSON array
    subheadings TEXT,       -- JSON array
    cached_at TEXT DEFAULT (datetime('now', 'localtime'))
);
```

缓存策略：MeSH 术语更新频率极低（每年一次），缓存可长期有效。

#### 1.4 自适应检索式生成

```python
def build_adaptive_query(concepts: list[ConceptDimension],
                         filters: dict) -> SearchStrategy:
    """生成自适应检索式，自动选择宽/中/窄三档中最合适的。

    流程：
    1. 生成三档检索式
    2. 用中档 esearch 取 total_count（retmax=0 仅取计数）
    3. 根据结果自动选择：
       - total_count > 500 -> 用窄档
       - total_count 10-500 -> 用中档（推荐）
       - total_count < 10 -> 用宽档
    4. 如用户已设 max_results，目标范围参考 max_results * 5 ~ max_results * 50
    """
```

三档检索式示例（以"化疗后中性粒细胞减少的预测因子"为例）：

```
# 窄档：全 MeSH + 全 AND
("Neutropenia"[MeSH Terms] OR "Chemotherapy-Induced Febrile Neutropenia"[MeSH Terms])
AND ("Monocytes"[MeSH Terms] OR "Lymphocytes"[MeSH Terms])
AND ("Antineoplastic Agents"[MeSH Terms])
AND ("Risk Factors"[MeSH Terms] OR "Predictive Value of Tests"[MeSH Terms])

# 中档：MeSH + 自由词 + AND（推荐默认）
("Neutropenia"[MeSH Terms] OR "neutropenia"[Title/Abstract] OR "febrile neutropenia"[Title/Abstract])
AND ("Monocytes"[MeSH Terms] OR "Lymphocytes"[MeSH Terms] OR "monocyte"[Title/Abstract] OR "lymphocyte"[Title/Abstract])
AND ("Antineoplastic Agents"[MeSH Terms] OR "chemotherapy"[Title/Abstract])
AND ("predictor"[Title/Abstract] OR "risk factor"[Title/Abstract])

# 宽档：自由词 + 同义词 + OR 为主
(neutropenia OR "febrile neutropenia" OR CIN OR FN OR "neutrophil nadir")
AND (monocyte OR lymphocyte OR monocytopenia OR lymphopenia OR AMC OR ALC)
AND (chemotherapy OR "chemotherapy-induced" OR "cytotoxic chemotherapy")
```

### Step 2：多轮检索（pubmed.py）

#### 2.1 三轮检索流程

```
┌─────────────────────────────────────────────────┐
│  Round 1：核心检索                                │
│  - esearch(term=自适应选择的检索式, retmax=50)    │
│  - efetch 获取所有候选文献详情                    │
│  - 记录 PubMed 返回的排序位置（relevance_rank）   │
│  输出：候选文献列表（最多50篇）                   │
└──────────────────────┬──────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────┐
│  Round 2：相关文献扩展（可选，用户勾选）           │
│  - 取 Round 1 前 3-5 篇文献的 PMID               │
│  - elink(cmd=neighbor, linkname=pubmed_pubmed)   │
│    并行查询每篇的 Related Articles                │
│  - 合并去重，每篇扩展最多 5 篇                   │
│  - efetch 获取新增文献详情                       │
│  输出：扩展后的文献列表                           │
└──────────────────────┬──────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────┐
│  Round 3：引文排序（可选，用户勾选）               │
│  - 主排序：elink citedin 查 PubMed 内被引        │
│    elink?id=PMID&cmd=neighbor                    │
│    &linkname=pubmed_pubmed_citedin               │
│    统计每篇的 citedin_count                      │
│  - 可选增强：Semantic Scholar 批量查全网被引      │
│    POST /paper/batch?fields=citationCount        │
│    （有 API Key 且用户选择时启用）                 │
│  - 计算综合评分并排序                             │
│  输出：排序后的文献列表                           │
└──────────────────────┬──────────────────────────┘
                       ↓
              截取 top N 返回给用户
```

#### 2.2 elink 相关文献 + 被引查询

```python
def get_related_articles(pmids: list[str], per_article: int = 5) -> list[str]:
    """获取相关文献 PMID 列表（并行查询）。

    API:
        GET https://eutils.ncbi.nlm.nih.gov/entrez/eutils/elink.fcgi
            ?dbfrom=pubmed&db=pubmed
            &id=PMID1&id=PMID2&...
            &cmd=neighbor
            &linkname=pubmed_pubmed

    返回的 XML 中，<LinkName>pubmed_pubmed</LinkName> 组下的
    <Link><Id>...</Id></Link> 即相关文献 PMID（已按相关度排序）

    每篇取前 per_article 篇，合并去重
    """
```

```python
def get_citation_counts_via_elink(pmids: list[str]) -> dict[str, int]:
    """通过 PubMed elink 查询被引次数。

    API:
        GET https://eutils.ncbi.nlm.nih.gov/entrez/eutils/elink.fcgi
            ?dbfrom=pubmed&db=pubmed
            &id=PMID1&id=PMID2&...
            &cmd=neighbor
            &linkname=pubmed_pubmed_citedin

    返回的 XML 中，<LinkName>pubmed_pubmed_citedin</LinkName> 组下的
    <Link> 数量即为该文献在 PubMed 中的被引次数。

    返回：{pmid: citedin_count}

    优势：
    - 无需额外 API 依赖（和 esearch 同一个 E-utilities 服务）
    - 稳定性远优于 Semantic Scholar
    - 与 NCBI API Key 频率限制共享（10次/秒有Key）

    局限：
    - 仅统计 PubMed 内引用，不含非 PubMed 期刊
    - 新发表文献可能被引较少
    """
```

#### 2.3 引文排序（citation_ranker.py）-- 优化版

**优化点**：主排序用 PubMed elink citedin（稳定），Semantic Scholar 降级为可选增强。

```python
def rank_articles(articles: list[Article],
                  use_semantic_scholar: bool = False) -> list[Article]:
    """引文排序，计算综合评分。

    评分公式：
        score = 0.4 * relevance_score    # PubMed 排序位置归一化
              + 0.3 * recency_score      # 发表年份归一化
              + 0.3 * citation_score     # 被引次数归一化

    被引数据来源（优先级）：
    1. SQLite citation_cache（7天有效）
    2. PubMed elink citedin（主数据源，稳定）
    3. Semantic Scholar batch API（可选增强，有Key时使用）

    citation_score 归一化：
    - 有被引数据：log(citation_count + 1) / log(max_citation + 1)
    - 无被引数据：0.0
    """
```

**引文数据缓存表**（在 db.py 中新增）：
```sql
CREATE TABLE IF NOT EXISTS citation_cache (
    pmid TEXT PRIMARY KEY,
    citation_count INTEGER,
    source TEXT,            -- 'elink' 或 'semantic_scholar'
    cached_at TEXT DEFAULT (datetime('now', 'localtime'))
);
```

缓存有效期：7 天（被引数据会变化，但不需要实时）。

## 五、数据模型（models.py）

```python
from dataclasses import dataclass, field
from typing import Optional


@dataclass
class MeshTerm:
    """MeSH 术语信息"""
    term: str                    # 精确 MeSH 名称
    ui: str                      # D 编号
    tree_numbers: list[str]      # 树号
    entry_terms: list[str]       # 入口词
    subheadings: list[str]       # 允许的子树限定符


@dataclass
class ConceptDimension:
    """概念维度"""
    name: str                    # 维度名称
    english_terms: list[str]     # 英文自由词
    mesh_terms: list[MeshTerm]   # 验证后的 MeSH 术语（空列表表示验证全部失败）
    failed_mesh: list[str]       # 验证失败的候选词
    synonyms: list[str]          # 同义词/缩写


@dataclass
class SearchStrategy:
    """检索策略"""
    query: str                          # 最终使用的 Boolean 检索式
    query_level: str                    # "narrow" / "medium" / "broad"
    concepts: list[ConceptDimension]    # 概念维度列表
    filters: dict                       # 过滤条件
    total_count: int = 0                # esearch 返回的总结果数
    # filters = {
    #     "date_range": ("2018", "2024"),
    #     "article_types": ["Journal Article", "Meta-Analysis"],
    #     "language": "English",
    # }


@dataclass
class Article:
    """文献"""
    pmid: str
    title: str
    abstract: str
    authors: str
    journal: str
    pub_date: str
    doi: str
    # 检索元信息
    source: str = "core"              # core / related
    relevance_rank: int = 0           # PubMed 排序位置（0 = 第一篇）
    citation_count: int = 0           # 被引次数
    citation_source: str = ""         # "elink" / "semantic_scholar" / "cache"
    final_score: float = 0.0          # 综合评分（0-1）
```

## 八、API 调用清单

| 步骤 | API | 端点 | 频率限制 | 用途 | 缓存 |
|------|-----|------|---------|------|------|
| 1.2 | DeepSeek | `POST /chat/completions` | 按 token | 自然语言 -> 概念拆解 | 无 |
| 1.3 | MeSH REST | `GET /lookup/descriptor?label=X` | 无限制 | 查 MeSH D 编号 | SQLite 永久 |
| 1.3 | MeSH REST | `GET /D编号.json` | 无限制 | 取 MeSH 详情 | SQLite 永久 |

| 2.1 | PubMed | `GET esearch.fcgi` | 3次/秒 | 核心 Boolean 检索 | 无 |
| 2.1 | PubMed | `GET efetch.fcgi` | 3次/秒 | 获取文献详情 XML | 无 |
| 2.2 | PubMed | `GET elink.fcgi?linkname=pubmed_pubmed` | 3次/秒 | 相关文献扩展 | 无 |
| 2.3 | PubMed | `GET elink.fcgi?linkname=pubmed_pubmed_citedin` | 3次/秒 | 被引次数（主） | SQLite 7天 |
| 2.3* | Semantic Scholar | `POST /paper/batch` | ~100次/5分钟 | 被引次数（可选增强） | SQLite 7天 |

- 申请 NCBI API Key（免费）可将 PubMed 频率从 3次/秒 -> 10次/秒

- 并行验证 MeSH 时限制 max_workers=3，避免触发限流

## 十二、错误处理与降级策略

| 场景 | 降级方案 | 用户感知 |
|------|---------|---------|
| DeepSeek 查询优化失败 | 回退为用户原始关键词直接 esearch（当前行为） | 提示"智能优化不可用，使用基础检索" |
| MeSH REST API 超时 | 跳过 MeSH 验证，直接使用 LLM 生成的候选词 | 标注"MeSH 验证跳过" |
| 某个概念维度的 MeSH 全部验证失败 | 该维度仅使用自由词 + 同义词（无 [MeSH Terms]） | 标注哪些维度无 MeSH |
| esearch 返回 0 结果 | 自动切换宽档重试；仍为 0 则提示用户 | 提示"尝试扩大检索范围" |
| 自适应：中档结果 >500 | 自动切换窄档 | 标注"已自动收紧检索" |
| 自适应：中档结果 <10 | 自动切换宽档 | 标注"已自动扩大检索" |
| elink 相关文献扩展失败 | 跳过扩展，仅使用核心检索结果 | 标注"扩展不可用" |
| elink citedin 失败 | 跳过引文排序，仅按 PubMed relevance + 时间排序 | 标注"引文排序跳过" |
| Semantic Scholar 429 限流 | 回退为 elink citedin 数据 | 无感知（自动降级） |
| efetch XML 解析失败 | 返回已解析的部分文献 | 标注"N篇解析失败" |
| 用户编辑检索式后语法错误 | try/except 捕获 esearch 错误 | 提示"检索式语法错误，请检查" |
