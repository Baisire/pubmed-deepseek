# 对话窗口功能模块设计方案

> 项目编号：a6 | 设计日期：2026-07-31 | 模块版本：v1.0
> 参考界面：metaso.cn 对话模式 | 技术框架：Streamlit
> 定位：在现有"关键词检索 + 分析报告"流程之上，新增"自由对话"交互范式，支持多模型调度

---

## 一、设计背景与目标

### 1.1 现状分析

当前应用（[app.py](file:///d:/trae/项目16：接单/a6_医学PubMed检索/streamlit/app.py)）的交互模式是**单轮命令式**：

```
用户输入关键词 -> 点击"开始检索" -> 等待 -> 查看报告 -> 结束
```

这种模式的局限：
- **无上下文延续**：每次检索独立，无法基于上一次结果追问
- **无自由交互**：用户只能选 translate/summary/review 三种固定模式，无法自定义需求
- **单模型锁定**：硬编码 `model="deepseek-chat"`（[app.py#L508](file:///d:/trae/项目16：接单/a6_医学PubMed检索/streamlit/app.py#L508)），无法切换
- **无工具调用**：AI 不能主动检索文献，只能被动接收检索结果后分析

### 1.2 设计目标

参考 metaso.cn 的对话模式，设计一个**多轮对话窗口**，实现：

| 目标 | 说明 |
|------|------|
| 自由对话 | 用户用自然语言与 AI 多轮交互，支持追问、修正、深入 |
| 多模型调度 | 可切换 DeepSeek / OpenAI / Claude / Qwen 等不同 LLM |
| 工具调用 | AI 可主动调用 PubMed 检索、文献分析等工具完成任务 |
| 上下文记忆 | 对话历史持久化，跨会话可恢复 |
| 与现有模式共存 | 对话模式与原有检索模式并列，用户可自由切换 |

### 1.3 参考分析：metaso.cn 对话模式

根据调研，metaso.cn 的核心设计特征：

| 特征 | metaso.cn 实现 | 本方案借鉴 |
|------|---------------|-----------|
| 三模式并列 | 搜索 / 对话 / 专题 顶部切换 | 检索 / 对话 顶部切换 |
| 多轮对话 | 基于上下文接续回答，可追问 | 同 |
| 深度档位 | 简洁 / 深入 / 研究 | 快速 / 标准 / 深度 |
| 左侧边栏 | 历史 / 专题 / 设置 | 对话历史 / 模型设置 |
| 结构化输出 | 大纲、思维导图、导出 | Markdown 报告 + 导出 |
| 来源标注 | 结果附参考来源 | 文献标注 PMID/DOI |

## 三、交互流程设计

### 3.1 核心对话流程

```
用户输入消息
    │
    ├── 普通消息（无需工具）
    │       ↓
    │   意图识别（LLM 判断是否需要调用工具）
    │       │
    │       ├── 不需要工具 → 直接调用 LLM 生成回复
    │       │                   ↓
    │       │              渲染 AI 消息
    │       │
    │       └── 需要工具 → 进入工具调用流程（见 3.2）
    │
    └── 快捷指令（/ 开头）
            │
            ├── /检索 关键词   → 调用 PubMed 检索工具
            ├── /翻译          → 对上一轮文献结果执行翻译
            ├── /综述          → 对上一轮文献结果执行综述
            ├── /切换模型 名称 → 切换当前 LLM
            ├── /清空          → 清空当前对话
            └── /帮助          → 显示帮助信息
```

### 3.2 工具调用流程（Function Calling）

```
用户: "帮我查一下化疗后中性粒细胞减少的预测因子"
    ↓
┌─────────────────────────────────────────┐
│  Step 1: 意图识别（LLM 第一轮调用）      │
│  输入：用户消息 + 工具列表               │
│  输出：function_call: pubmed_search      │
│        args: {                           │
│          "query": "chemotherapy-induced  │
│          neutropenia predictors",        │
│          "max_results": 8                │
│        }                                 │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  Step 2: 工具执行                        │
│  执行 pubmed_search(query, max_results)  │
│  → 调用现有 search_pubmed() + v3.0 语义  │
│    精排                                  │
│  → 返回文献列表 JSON                     │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  Step 3: 结果整合（LLM 第二轮调用）      │
│  输入：用户消息 + 工具返回结果           │
│  输出：自然语言回复 + 文献引用           │
│  → "已检索到 8 篇文献，核心发现是..."    │
└──────────────┬──────────────────────────┘
               ↓
          渲染 AI 消息（含工具调用记录 + 文献来源）
```

### 3.3 多轮对话上下文管理

```
对话历史 = [
    {role: "system",    content: "你是医学文献助手..."},
    {role: "user",      content: "查化疗后中性粒细胞减少的预测因子"},
    {role: "assistant", content: "已检索到8篇...",
     tool_calls: [{name: "pubmed_search", args: {...}, result: {...}}]},
    {role: "user",      content: "这些预测因子的cutoff值是多少？"},
    {role: "assistant", content: "根据文献，cutoff值如下..."},
    {role: "user",      content: "把第二篇文献翻译成中文"},   ← 引用上文
    {role: "assistant", content: "（翻译结果）"},
]

上下文窗口策略：
- 保留最近 20 轮对话（可配置）
- 超出时：保留 system + 最近 N 轮 + 首轮
- 工具调用结果过长时：摘要后保留（避免 token 爆炸）
```

### 3.4 模型切换流程

```
用户点击模型下拉框
    │
    ├── 选择新模型（如从 DeepSeek 切到 GPT-4o）
    │       ↓
    │   模型调度器加载模型配置
    │       │
    │       ├── 验证 API Key 是否可用
    │       │     ├── 可用 → 切换成功，提示"已切换到 GPT-4o"
    │       │     └── 不可用 → 提示"该模型需要 OpenAI API Key，
    │       │                  请在设置中配置"
    │       │
    │       └── 更新 session_state["current_model"]
    │
    └── 后续对话使用新模型
        │
        └── 上下文连续：对话历史不丢失，
            新模型继承完整上下文继续对话
```

### 3.5 回答深度档位

参考 metaso.cn 的"简洁/深入/研究"三档：

| 档位 | 行为 | System Prompt 调整 | 适用场景 |
|------|------|-------------------|---------|
| **快速** | 直接回答，不调用工具，200 字以内 | "简洁回答，不超过200字" | 快速事实查询 |
| **标准** | 可调用工具，结构化回答，500-1000 字 | "标准回答，结构化输出" | 日常文献调研（默认） |
| **深度** | 必调工具（如需），详尽分析，2000+ 字，附来源 | "深度分析，引用来源，多角度" | 深度综述、对比分析 |

**context_manager.py** - 上下文窗口管理
```python
def build_context(messages: list[dict], 
                  max_tokens: int = 8000) -> list[dict]:
    """构建符合 token 限制的上下文。

    策略：
```

### 5.2 适配层设计（核心）

不同 LLM provider 的 API 差异需要适配层屏蔽：

| 差异点 | OpenAI/DeepSeek/Qwen | Anthropic | 适配策略 |
|--------|---------------------|-----------|---------|
| SDK | openai SDK 原生 | anthropic SDK | 根据 provider 选择 SDK |
| System 消息 | messages 中 role=system | 独立 system 参数 | 适配层拆分 |
| 工具调用 | function_call / tool_calls | tool_use block | 适配层转换格式 |
| 流式输出 | stream=True, delta.content | stream=True, content_block_delta | 适配层统一 chunk 格式 |
| 最大 token | max_tokens 参数 | max_tokens 参数 | 直接透传 |

```python
# model_adapter.py 核心逻辑

def call_model(config: ModelConfig, messages: list[dict],
               tools: list[dict] | None, api_key: str,
               stream: bool = False) -> dict:
    """统一调用入口。"""
    if config.provider in ("deepseek", "openai", "qwen"):
        return _call_openai_compatible(config, messages, tools,
                                        api_key, stream)
    elif config.provider == "anthropic":
        return _call_anthropic(config, messages, tools,
                               api_key, stream)
    else:
        raise ValueError(f"Unsupported provider: {config.provider}")


def _call_openai_compatible(config, messages, tools, api_key, stream):
    """OpenAI 兼容接口（DeepSeek/OpenAI/Qwen 通用）。"""
    client = OpenAI(api_key=api_key, base_url=config.api_base)
    kwargs = {
        "model": config.model_id,
        "messages": messages,
        "temperature": 0.4,
        "max_tokens": config.max_tokens,
    }
    if tools:
        kwargs["tools"] = tools
    if stream:
        kwargs["stream"] = True
    
    response = client.chat.completions.create(**kwargs)
    return _parse_openai_response(response)


def _call_anthropic(config, messages, tools, api_key, stream):
    """Anthropic 专属适配。"""
    import anthropic
    client = anthropic.Anthropic(api_key=api_key)
    
    # 拆分 system 消息
    system_msg = ""
    chat_msgs = []
    for msg in messages:
        if msg["role"] == "system":
            system_msg += msg["content"] + "\n"
        else:
            chat_msgs.append(msg)
    
    # 转换工具格式
    anthropic_tools = _convert_tools_to_anthropic(tools) if tools else None
    
    response = client.messages.create(
        model=config.model_id,
        system=system_msg,
        messages=chat_msgs,
        tools=anthropic_tools,
        max_tokens=config.max_tokens,
    )
    return _parse_anthropic_response(response)
```

### 5.3 降级策略

```
主模型调用失败
    ↓
┌──────────────────────────────────────────┐
│  降级链（按优先级）                        │
│                                          │
│  1. 重试主模型（最多 2 次，间隔 1s）       │
│  2. 切换到同 provider 的轻量模型           │
```

```python
def route_with_tools(message, context, model_id, tools, api_keys):
```

```python
def estimate_cost(model_id: str, input_tokens: int, 
                  output_tokens: int) -> float:

    cost = (input_tokens + output_tokens) / 1000 * config.cost_per_1k
```

```python
def stream_model_response(config, messages, api_key):

    response = client.chat.completions.create(
        model=config.model_id,
```

## 八、安全与隐私设计

| 风险 | 措施 |
|------|------|
| API Key 泄露 | 用户输入的 Key 加密存储于 SQLite，不显示明文，不写入日志 |
| 对话内容泄露 | 对话数据仅存本地 SQLite，不发送到第三方（除 LLM API 外） |
| 多模型 Key 混用 | Key 按 provider 隔离，切换模型时自动选用对应 Key |
| 工具调用安全 | 工具执行结果需脱敏（如不返回完整摘要给用户端 JS） |
| Token 滥用 | 复用现有 usage_log 配额机制，对话也计入用量统计 |
